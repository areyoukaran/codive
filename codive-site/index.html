Four questions, answered before your first coffee.

Every screen in Codive exists to answer one of them. If a screen cannot, it does not ship.

What changed?

Commits, merges and releases since you last looked — grouped by repository, summarized in a sentence each, not mirrored as a raw feed.

What needs me?

Reviews assigned to you, failing checks on branches you own, threads where someone asked you a question and nobody answered.

What is rotting?

Pull requests past fourteen days, issues with no reply, review turnaround creeping from 9h to 31h, dependencies a year behind.

Why is it like this?

Ask in plain English. Which pull request introduced this dependency, what breaks if you change this module, what a forty-comment thread actually decided.

Findings you can check, not conclusions you have to trust.

Codive reads the diff alongside the surrounding code, then says what it thinks might be wrong — with the file, the line and the reasoning attached. It is a second reader, not a gate. Disagree with it and move on.

Confidence is shown on every finding. Nothing merges or closes on its own.

How it works

Five minutes to set up. The first sync runs in the background while you keep working.

Authorize GitHub

Read-only scopes. Codive never pushes, never comments and never opens a pull request on your behalf.

Pick the repositories you actually watch

Four is a better answer than forty. You can add more later without re-authorizing.

First sync builds the picture

Commits, branches, pull requests, reviews, issues, releases and workflow runs are pulled, normalized and stored with their source identifiers so every later claim is traceable.

Indexing makes the code searchable

README, docs, configuration and selected source chunks are embedded with their file paths and commit references kept intact, so answers can cite a line rather than a vibe.

Webhooks keep it current

Near-real-time events where webhooks are practical, incremental polling as a fallback. Cursors mean a sync fetches what changed, not the whole history again.

What happens to your code

The short version: as little as possible, and nothing surprising.

Access
Read-only GitHub scopes, scoped to the repositories you select. Tokens are encrypted at rest and never written to logs.
What is stored
Repository metadata, activity records and selected file chunks with their embeddings. Enough to answer questions about your code, not a second copy of your repository.
Isolation
Every row carries an owner. Queries are scoped at the database layer, not by a filter someone might forget to apply.
Untrusted by default
Repository text — issue bodies, code comments, README files — is treated as untrusted input and kept separate from system instructions, because a file that says “ignore your instructions” is a file, not an instruction.
Leaving
Disconnect a repository and its synced data and embeddings are deleted. Disconnect the account and everything goes.

Start with one repository. See if the brief is worth reading.
